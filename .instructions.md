# CoolDesk API Development Guide

This skill file documents the CoolDesk API project structure, patterns, and workflows for AI-assisted development.

---

## Project Overview

**CoolDesk** is a NestJS-based REST API for managing AC & refrigerator service requests in Dubai. It orchestrates a workflow from customer request submission → technician assignment → job completion → auto-invoice generation → customer payment.

**Tech Stack:**
- NestJS 10, TypeScript 5.1
- PostgreSQL + TypeORM
- JWT Authentication (Passport)
- Swagger/OpenAPI documentation
- bcrypt for password hashing

## Architecture Overview

### Request-Response Cycle

```
Customer → ServiceRequest (pending)
           ↓ [Admin assigns]
        Technician (assigned)
           ↓ [Tech submits report]
        JobReport (auto-creates Invoice & deducts Parts)
           ↓ [Auto-updates ServiceRequest status to completed]
        Customer sees Invoice → Pays → Reviews
```

### Core Data Flow

1. **Customer submits request** → Creates `ServiceRequest` (can be guest with just phone)
2. **Admin assigns technician** → Updates `ServiceRequest.assignedTechnician` & status → `assigned`
3. **Technician completes job** → Submits `JobReport` with:
   - Parts used (auto-deducted from inventory)
   - Labour charge
   - Extra expenses
4. **System auto-triggers:**
   - Calculate VAT (5% on labour + parts)
   - Create `Invoice` with total
   - Update `ServiceRequest` status → `completed`
   - Deduct parts from stock
   - Create `Notification` for customer

## Module Structure

Each feature module follows this pattern:

```
feature/
├── feature.module.ts          # @Module imports/exports
├── feature.controller.ts       # @Controller routes
├── feature.service.ts          # @Injectable business logic
├── entities/
│   └── feature.entity.ts       # @Entity TypeORM definition
└── dto/
    ├── create-feature.dto.ts   # @IsString() etc. validation
    └── update-feature.dto.ts
```

### Module Import Checklist

When adding a new module:
1. Create `YourFeature.module.ts` with `@Module({ imports: [TypeOrmModule.forFeature([Entity])] })`
2. Add to `app.module.ts` imports array
3. Inject service into controller: `constructor(private service: YourFeatureService) {}`
4. Mark protected routes with `@UseGuards(JwtAuthGuard)`

## Key Conventions

### 1. Service Request Lifecycle

**Status Enum:** `PENDING → ASSIGNED → IN_PROGRESS → COMPLETED` (or `CANCELLED`)

```typescript
export enum RequestStatus {
  PENDING = 'pending',
  ASSIGNED = 'assigned',
  IN_PROGRESS = 'in_progress',
  COMPLETED = 'completed',
  CANCELLED = 'cancelled',
}
```

**Update Status Pattern:**
```typescript
// In ServiceRequestsService
async updateStatus(id: string, newStatus: RequestStatus) {
  const sr = await this.repo.update(id, { status: newStatus });
  // Trigger notification
  await this.notificationsService.create({
    customerId: sr.customerId,
    message: `Job ${sr.jobRef} status: ${newStatus}`
  });
  return sr;
}
```

### 2. Auto-Invoice from Job Report

**When technician submits job report:**

```typescript
// In JobReportsService
async submitJobReport(srId: string, dto: SubmitJobReportDto) {
  const sr = await this.serviceRequestsRepo.findOne(srId);
  
  // 1. Create JobReport
  const jobReport = await this.repo.create({
    serviceRequest: sr,
    technician: sr.assignedTechnician,
    faultFound: dto.faultFound,
    diagnosisNotes: dto.diagnosisNotes,
    labourCharge: dto.labourCharge,
  });
  
  // 2. Handle parts: deduct stock + calculate total
  jobReport.partsTotal = 0;
  for (const partUsage of dto.parts) {
    const part = await this.partsRepo.findOne(partUsage.partId);
    part.stockQuantity -= partUsage.quantityUsed;
    await this.partsRepo.save(part);
    jobReport.partsTotal += part.sellingPrice * partUsage.quantityUsed;
  }
  
  // 3. Auto-calculate amounts
  jobReport.vatAmount = (jobReport.labourCharge + jobReport.partsTotal) * 0.05;
  jobReport.grandTotal = jobReport.labourCharge + jobReport.partsTotal 
                       + jobReport.extraExpensesTotal + jobReport.vatAmount;
  
  // 4. Save JobReport
  await this.repo.save(jobReport);
  
  // 5. Auto-create Invoice
  const invoice = await this.invoicesService.createFromJobReport(jobReport);
  
  // 6. Update ServiceRequest status
  await this.serviceRequestsService.updateStatus(srId, RequestStatus.COMPLETED);
}
```

**When technician creates an instant phone-call job:**

```typescript
// In JobReportsService
async submitInstantJob(technicianId: string, dto: SubmitInstantJobDto) {
  // 1. Upsert customer by phone
  // 2. Create ServiceRequest from payload
  // 3. Auto-assign logged-in technician
  // 4. Reuse completed-job submission flow
  // 5. Save JobReport + Invoice and mark request completed
}
```

### 3. Authentication & Guards

**Routes requiring JWT:**
```typescript
@UseGuards(JwtAuthGuard)
@Get()
getAllCustomers() { ... }
```

**Routes that are public:**
```typescript
// No @UseGuards decorator
@Post()
registerCustomer(@Body() dto: RegisterDto) { ... }
```

**JWT Strategy (in `auth/jwt.strategy.ts`):**
- Token extracted from `Authorization: Bearer <token>` header
- Payload contains `{ userId, role }`
- Guard validates token expiry & signature

### 4. Entity Relations

**Key Patterns:**

```typescript
// Customer → many ServiceRequests (one-to-many)
@OneToMany(() => ServiceRequest, (sr) => sr.customer)
serviceRequests: ServiceRequest[];

// ServiceRequest → single Technician (many-to-one)
@ManyToOne(() => Technician, (t) => t.serviceRequests)
assignedTechnician?: Technician;

// JobReport → ServiceRequest (one-to-one)
@OneToOne(() => ServiceRequest, (sr) => sr.jobReport)
@JoinColumn()
serviceRequest: ServiceRequest;
```

**When querying related data:**
```typescript
// Eager load to avoid N+1 queries
const jobReport = await this.repo.findOne(id, {
  relations: ['technician', 'serviceRequest', 'parts']
});
```

### 5. Error Handling

**Standard error responses:**

```typescript
// In service
if (!customer) {
  throw new NotFoundException('Customer not found');
}

if (customer.isRegistered && !hasPassword) {
  throw new BadRequestException('Registered customer must have password');
}

if (!validToken) {
  throw new UnauthorizedException('Invalid or expired token');
}
```

**Validation errors:**
- Use DTO decorators: `@IsString()`, `@IsNumber()`, `@IsNotEmpty()`, etc.
- ValidationPipe in `main.ts` auto-rejects invalid requests
- Return `400 Bad Request` with field errors

## Common Development Tasks

### Add a New API Endpoint

**Step 1: Create DTO**
```typescript
// feature/dto/create-feature.dto.ts
import { IsString, IsNumber, IsNotEmpty } from 'class-validator';

export class CreateFeatureDto {
  @IsString()
  @IsNotEmpty()
  name: string;

  @IsNumber()
  quantity: number;
}
```

**Step 2: Add Service Method**
```typescript
// feature/feature.service.ts
async createFeature(dto: CreateFeatureDto) {
  const entity = this.repo.create(dto);
  return this.repo.save(entity);
}
```

**Step 3: Add Controller Route**
```typescript
// feature/feature.controller.ts
@Post()
@UseGuards(JwtAuthGuard)
create(@Body() dto: CreateFeatureDto) {
  return this.service.createFeature(dto);
}
```

**Step 4: Update Swagger (in main.ts)**
```typescript
.addTag('feature', 'Feature management')
```

### Add a New Entity

**Step 1: Create Entity File**
```typescript
// feature/entities/feature.entity.ts
import { Entity, PrimaryGeneratedColumn, Column, ManyToOne } from 'typeorm';
import { Parent } from '../parent/entities/parent.entity';

@Entity('features')
export class Feature {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column()
  name: string;

  @ManyToOne(() => Parent, (p) => p.features)
  parent: Parent;

  @CreateDateColumn()
  createdAt: Date;
}
```

**Step 2: Update Module**
```typescript
// feature/feature.module.ts
@Module({
  imports: [TypeOrmModule.forFeature([Feature])], // Add entity
  controllers: [FeatureController],
  providers: [FeatureService],
})
export class FeatureModule {}
```

**Step 3: Add to AppModule (if new module)**
```typescript
// app.module.ts
import { FeatureModule } from './feature/feature.module';

@Module({
  imports: [
    ...,
    FeatureModule, // Add here
  ],
})
export class AppModule {}
```

### Modify Service Request Status

**Workflow:**
```typescript
// In service-requests.service.ts
async updateStatus(id: string, newStatus: RequestStatus) {
  const sr = await this.repo.update(id, { status: newStatus });
  
  // Notify customer
  if (newStatus === RequestStatus.ASSIGNED) {
    await this.notificationsService.create({
      customerId: sr.customerId,
      title: 'Technician Assigned',
      message: `${sr.assignedTechnician.name} is assigned to job ${sr.jobRef}`
    });
  }
  
  return sr;
}
```

### Create Recurring Request from History

**Pattern:**
```typescript
// In service-requests.service.ts
async createRecurring(customerId: string, previousRequestId: string) {
  const previous = await this.repo.findOne(previousRequestId);
  
  const newRequest = this.repo.create({
    customer: { id: customerId },
    serviceType: previous.serviceType,
    equipmentType: previous.equipmentType,
    equipmentBrand: previous.equipmentBrand,
    equipmentModel: previous.equipmentModel,
    problemDescription: previous.problemDescription,
    address: previous.address,
    lat: previous.lat,
    lng: previous.lng,
    status: RequestStatus.PENDING,
  });
  
  return this.repo.save(newRequest);
}
```

### Handle Parts Stock Deduction

**Pattern:**
```typescript
// In job-reports.service.ts
async deductParts(jobReport: JobReport, partUsages: JobPartDto[]) {
  let totalCost = 0;
  
  for (const usage of partUsages) {
    const part = await this.partsRepo.findOne(usage.partId);
    
    if (part.stockQuantity < usage.quantityUsed) {
      throw new BadRequestException(`Insufficient stock for ${part.partName}`);
    }
    
    // Deduct
    part.stockQuantity -= usage.quantityUsed;
    await this.partsRepo.save(part);
    
    // Track usage
    totalCost += part.sellingPrice * usage.quantityUsed;
  }
  
  return totalCost;
}
```

### Technician Instant-Job Pattern

Use this when the technician receives the job directly from the customer instead of through dispatcher assignment.

**Endpoint:** `POST /job-reports/instant`

**Rules:**
- Same form contains both service-request fields and job-report fields
- Customer is matched by phone; create if not found
- ServiceRequest is auto-created with source `phone`
- Logged-in technician becomes `assignedTechnician`
- ServiceRequest is marked `completed` after report save
- Invoice generation and parts deduction work exactly like normal report submission

## Database

### Synchronize Mode

- **Development (`NODE_ENV=development`)**: `synchronize: true` → auto-creates tables from entities
- **Production (`NODE_ENV=production`)**: `synchronize: false` → requires migrations

### Logging Queries

In `app.module.ts`:
```typescript
logging: config.get('NODE_ENV') === 'development', // Log SQL queries in dev
```

### Common Queries

**Find with relations:**
```typescript
await this.repo.findOne(id, {
  relations: ['customer', 'technician', 'jobReport']
});
```

**Filter with conditions:**
```typescript
await this.repo.find({
  where: { status: RequestStatus.PENDING, customerId: customerId },
  relations: ['customer']
});
```

## Debugging Tips

**1. TypeORM Query Logging**
- Set `logging: true` in TypeOrmModule config
- See SQL queries in console

**2. JWT Token Inspection**
- Decode JWT at https://jwt.io
- Check payload { userId, role, iat, exp }

**3. Database Inspection**
- Query directly: `psql -U postgres -d cooldesk`
- Or use DBeaver, pgAdmin for GUI

**4. Validation Errors**
- Check DTO decorators match request body
- ValidationPipe will reject mismatches

- `201`: Created
- `400`: Bad Request (validation failed)
